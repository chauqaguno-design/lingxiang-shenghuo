# 简历描述与面试准备

## 项目描述

**邻享生活——本地生活优惠服务平台**

**技术栈：** Spring Boot、MyBatis-Plus、MySQL、Redis、Lua、Redisson、RocketMQ、Caffeine。

**项目简介：** 面向本地商户优惠活动，提供商户查询、限量优惠券抢购、订单管理及模拟支付。围绕热点查询和并发抢券，完善缓存、请求限流、异步下单与超时订单处理。

- 使用 Redis + Lua 原子校验活动时间、库存与用户资格，通过预占记录支持重试；结合 MySQL 条件扣减和联合唯一约束，防止超卖与重复订单。
- 基于本地消息表与 RocketMQ 实现异步建单，通过请求状态和消费者本地事务处理重复投递，提供订单处理结果查询和中断请求恢复。
- 针对商户查询使用空值缓存、逻辑过期与互斥异步重建；对热点优惠券展示构建 Caffeine + Redis 两级缓存，并设置容量和过期边界。
- 基于注解、AOP、Redis ZSet/Lua 实现用户和活动维度的滑动窗口限流，采用 Redis 时间及唯一请求成员避免同毫秒覆盖。
- 使用 RocketMQ 延迟消息与定时扫描关闭未支付订单，通过条件更新协调支付和关单，并以订单预占状态实现库存幂等回补。
- 使用 JMeter 对三种查询模式与抢券场景进行本机测试，核对最终订单数、重复订单和库存；具体数据见实测报告。

不要把本机短时测试写成生产峰值，不要虚构日活、真实交易额或微服务规模。上述代码完成不等于已经掌握；能解释并复现后再写到投递版本。

## 高频追问

| 追问 | 回答落点 | 对照代码 |
|---|---|---|
| Lua 已经扣了，Java 崩了怎么办？ | 持久化请求先落库，同订单号幂等预占，恢复 PREPARING | submit / prepare |
| MQ 发出去了，但响应丢了？ | outbox 未确认就重发；消费者幂等，不立刻补库存 | OrderJobs.relay / create |
| MQ 是否保证只消费一次？ | 不保证；业务事务、状态检查和唯一键负责去重 | OrderLifecycle.create |
| 为什么入口还写 MySQL？ | 为持久化恢复付出开销，不能同时宣称纯 Redis 极限吞吐 | seckill_request |
| 扣库存后插单失败？ | 同一本地事务整体回滚，补偿在失败事务外处理 | create / H2 tests |
| Redis 和数据库会不会短暂不一致？ | 会；区分预占与实际库存，通过状态与补偿收敛 | ReservationStore |
| 支付和关单谁先成功？ | 同一行 status=1 条件更新，过期条件互补 | pay / close |
| 缓存更新如何通知其他实例？ | L1 为 5 秒；并发回源旧值可能经历 Redis 60 秒 TTL 及 L1 窗口，未实现强一致广播 | VoucherDisplayCache |
| 锁到期了是否会加两次库存？ | 扫描锁仅减少重复工作；数据库 CAS 和补偿 Lua 做最终保护 | OrderJobs / release-reservation.lua |
| 取消后为何不能重新购买？ | 本活动一人一券产品规则，唯一约束保留历史 | uk_order_user_voucher |

## 复习资料

先学自己项目用到的题，再拓展。关键词：Redis 缓存穿透/击穿、Lua 原子性、Redisson 看门狗；MySQL 行锁/唯一索引/事务回滚；RocketMQ 重复消费/发送失败/重试/死信/延迟消息；Spring 代理与事务边界。

可配合 [JavaGuide 的 Redis 知识总结](https://javaguide.cn/database/redis/redis-questions-01.html) 查基础题，再回到 [RocketMQ 官方消费文档](https://rocketmq.apache.org/docs/4.x/consumer/02push/) 和仓库代码验证。面试回答应以当前实现为准，不能背成“用了 MQ 就自动保证一致性”。
