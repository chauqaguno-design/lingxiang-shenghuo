# 接口与状态

所有接口同源，没有 /api 前缀。返回格式为 {"success":true,"data":...} 或 {"success":false,"errorMsg":"..."}。Java Long 统一输出字符串；页面不要把订单号转成 Number。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /demo/login | demo 模式，JSON {"phone":"13800000001"}，返回 token |
| GET | /demo/status | demo 模式返回开启状态 |
| GET | /shop-type/list | 商户分类 |
| GET | /shop/of/type?typeId=1&current=1 | 分类列表 |
| GET | /shop/{id} | 商户详情 |
| GET | /voucher/list/{shopId} | 商户券列表；不返回实时库存 |
| POST | /voucher-order/seckill/{voucherId} | 登录后抢券，返回受理订单号 |
| GET | /voucher-order/result/{orderId} | 查询自己的抢券请求与订单状态 |
| GET | /voucher-order/my | 当前用户最近 100 个已创建订单 |
| POST | /voucher-order/{orderId}/pay | demo 模拟支付，无真实扣款 |

登录接口拿到 token 后设置请求头 authorization。抢券可带 X-Request-Id（1～80 位字母、数字、下划线、横线）；同一用户同一请求标识重复调用返回原请求的结果。标识不能复用于另一个活动。

请求状态：PREPARING=准备预占，RESERVED=已预占等待建单，SUCCEEDED=已创建，FAILED=失败。
订单状态：1=待支付，2=已支付，4=已关闭。

返回订单号不表示已经建单，页面需要查询 result。SUCCEEDED 的请求对应订单仍可能后来超时关闭，应同时读取 orderStatus。

HTTP 401=未登录，429=用户限流，503=限流所需 Redis 暂不可用，500=未处理异常。库存不足、一人一券等业务拒绝使用 success=false。

旧管理写接口默认关闭，未交付商户管理角色系统。应用默认为本机演示，不能直接把 demo 登录开放到公网。
